Start with the overall system, understand how instructions and evidence enter the workflow, trace a real scenario, and then follow the implementation sequence. Your role as AI engineer: turn the scenario narrative into executable agent workflows with approved instructions, scoped tools, deterministic calculations, traceable explanations, controlled actions and measurable acceptance checks. This is a proposed design based on the supplied draft, Ali’s feedback and Sulieman’s architecture. It does not establish approved ownership or confirmed platform capabilities. Figures 5–6 apply the same building blocks to all four draft scenarios. Figure 7 shows your engineering assignment. The terms in everyday language Supervisor: the coordinator that chooses tasks and collects results. Specialist workflow: a focused task such as retrieving records or preparing an explanation; it does not require a separately trained model. Tool: a controlled function the application runs to read records, calculate or submit an approved change. Gold: the curated data tables the project has prepared for reliable queries. Retrieval / RAG: finding relevant approved passages and giving them to the model as reference material. Case state: a saved progress record of what was found, approved, submitted and still needs attention. Idempotency key: a unique operation key that helps prevent a repeated request from making the same change twice. These are concrete examples using the supplied synthetic demonstration draft, not live taxpayer transactions. Any tool behavior described is proposed application behavior to implement and verify. The application records approval against that payload. Before execution, the backend checks permissions and whether the data has changed. A stable operation key prevents repeated clicks or retries from submitting the same change twice. For the invoice, evidence tools identify the configured discrepancy and the agent prepares correction documents for approval. For the refund, evidence arrives in stages and changes which components are supported. The same workflow building blocks handle both, with different approved instructions and tool contracts. Reconciliation must preserve both the net tax change and the correct Emirate allocation. Disclosure must preserve the correct period and remove the same invoices from the next draft period. A numerically plausible answer can still be wrong if either allocation is lost. Scenario playbooks: reconciliation and disclosure Period allocation and arithmetic come from approved definitions and tools; the agents explain and coordinate.
